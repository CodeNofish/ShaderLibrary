依据检索到的 Unity/Unreal 技术文档及多项 Shader 实现资料，Silhouette（剪影/轮廓高亮）与 X-Ray（透视）效果在实时渲染中并非单一算法，而是根据遮挡判定机制和视觉表现形式分为多个独立的技术类别。以下是具体分类与对应算法：

一、 按“遮挡判定机制”分类
这是实现该效果最核心的底层差异，决定了效果的精度、性能开销及对管线的侵入程度。
分类   核心算法   原理与特点   适用场景
深度测试驱动 (ZTest Greater)   Multi-Pass ZTest   最经典方案。Shader 包含两个 Pass：1. X-Ray Pass：ZTest Greater + ZWrite Off，仅当当前像素深度 > 深度缓冲值（即被遮挡）时通过，绘制半透/发光效果；2. Normal Pass：ZTest LEqual，正常渲染未遮挡部分。局限：模型自身背对相机的面也可能触发 Greater 测试，导致“自透视”穿帮。   移动端、简单墙体遮挡提示、对自遮挡不敏感的场景。

模板缓冲驱动 (Stencil Buffer)   Stencil Masking   解决自遮挡的标准方案。1. 第一 Pass 正常渲染物体，同时向 Stencil Buffer 写入标记值（如 Ref=254）；2. X-Ray Pass 设置 Stencil Comp NotEqual 254，排除已标记为“自身可见”的像素，再结合 ZTest Greater 仅绘制被外部物体遮挡的部分。优势：精确区分“自身遮挡”与“外部遮挡”。   队友标记、复杂角色模型、MOBA/战术射击游戏标配。

屏幕空间深度纹理采样   Depth Texture Compare   URP/HDRP 单 Pass 方案。在片元着色器中采样 _CameraDepthTexture，将当前片元线性深度与场景背景深度逐像素比较。若当前深度 > 背景深度，则输出 X-Ray 颜色。优势：无需多 Pass，兼容 SRP Batch；可结合法线纹理做边缘检测。代价：需开启管线深度纹理，增加带宽消耗。   URP/HDRP 项目、需要单 Pass 集成的后处理风格效果。

后处理边缘检测 + 目标掩码   Sobel/Laplacian + Depth Mask   全屏批量方案。不修改目标物体 Shader，而是：1. 用专用相机或 RenderFeature 将目标物体渲染到临时 RT（目标掩码）；2. 后处理中对掩码 RT 做 Sobel/深度法线差分提取轮廓；3. 结合场景深度判断遮挡区域，叠加幽灵轮廓。优势：支持任意数量目标统一处理，不依赖模型顶点数。   大规模 RTS 单位标记、解谜高亮、团队副本指引。

二、 按“视觉表现形式”分类
在遮挡判定通过后，具体的着色算法决定了玩家看到的是什么效果：

纯色/渐变半透明填充 (Flat/Ghost Fill)
算法：直接输出固定颜色 + Alpha，或使用菲涅尔（Fresnel）公式 rim = 1 - dot(N, V) 使边缘亮、中心暗。
表现：经典的“幽灵”透视效果，被遮挡部分显示为半透明蓝色/红色人形。
资料确认：多篇教程指出菲涅尔边缘光是 X-Ray Pass 中最常用的增强可读性手段，避免纯色块与背景混淆。

轮廓描边 (Outline / Silhouette Edge)
算法细分：
顶点膨胀法：在 X-Ray Pass 中将顶点沿法线外扩，配合 Cull Front 只绘制背面膨胀部分作为描边。
屏幕空间边缘检测：对目标掩码 RT 做卷积差分提取边缘线。
Stencil 反向描边：第一 Pass 写入 Stencil，第二 Pass 用 Comp NotEqual 仅在未标记区域绘制，形成外轮廓。
表现：仅显示被遮挡物体的外轮廓线，内部透明，视觉干扰最小。

结构化透视 (Structural X-Ray)
算法：在 X-Ray Pass 中不使用纯色，而是采样内部结构贴图、骨骼动画或线框渲染，结合深度遮罩限定显示范围。
表现：医疗模拟中的骨骼透视、策略游戏中的建筑内部单位部署。资料明确指出此效果是 Outline 无法替代的，因为它传递的是“内部是什么样”而非仅仅“这里有东西”。

动态脉冲/呼吸效果 (Animated Pulse)
算法：在 X-Ray 输出上叠加 sin(time * speed) 或噪声纹理滚动，使透明度/亮度随时间周期性变化。
表现：增强“活跃目标”的视觉提示，区分静态障碍物与动态角色。

三、 关键实现注意事项（基于检索证据）
渲染队列顺序：X-Ray Pass 必须在不透明物体之后、透明物体之前渲染。资料强调引擎先绘制 Opaque 再绘制 Transparent，X-Ray 依赖已写入的深度缓冲，因此通常置于 Queue=Geometry+1 或利用 SRP 的 RenderFeature 精确控制注入点。
自遮挡问题：纯 ZTest Greater 方案在角色转身时会出现面部/手臂穿透自身躯干的错误高亮。Stencil 方案是生产环境中解决此问题的推荐做法，而非单纯依赖深度测试。
URP 兼容性：URP 不支持 GrabPass，必须使用 _CameraDepthTexture；且多 Pass Shader 需注意 SRP Batcher 兼容性，复杂逻辑建议改用 Scriptable Renderer Feature + 单独材质实现。
性能权衡：后处理全屏方案适合批量目标但固定开销较高；Per-Object 多 Pass 方案适合少量目标但 DrawCall 翻倍。资料建议根据目标数量阈值动态切换方案。
