依据检索到的 Unity/Unreal 官方文档及技术实现资料，Dither Transparency（抖动透明）在实时渲染中并非单一算法，而是根据**噪声源类型**、**时序处理机制**和**应用维度**分为多个独立的技术类别。其核心原理始终一致：利用 Alpha Test（`clip` / `discard`）代替 Alpha Blend，将连续透明度离散化为像素级的“保留/丢弃”决策，从而以不透明材质的渲染路径模拟半透明视觉。

### 一、 按“噪声源算法”分类
这是决定抖动图案视觉质量与性能开销的核心差异：

| 分类 | 核心算法 | 原理与特点 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **Bayer 有序抖动** | 4×4 / 8×8 Bayer Matrix | 使用预定义的阈值矩阵（如经典 4×4 矩阵含 16 个均匀分布值），通过屏幕坐标取模索引阈值，与 Alpha 比较后执行 `clip`。**特点**：零纹理带宽，纯 ALU 计算；但图案呈规则网格状，近距离观察有明显斜纹与阶梯感。 | 移动端、低端平台、植被/铁丝网等本身具颗粒结构的物体。Unity Shader Graph Dither 节点默认采用此算法。 |
| **蓝噪声抖动** | Blue Noise Texture | 采样预烘焙的蓝噪声纹理作为阈值源。蓝噪声在频域上抑制低频、保留高频，颗粒分布极度均匀，无规律条纹或聚集色块。**特点**：视觉平滑度远优于 Bayer；需额外纹理采样，但与 Lumen/TSR/TAA 的降噪器数学分布高度契合，时序累积后收敛更快。 | UE5 Dithered Opacity 推荐方案、次世代主机/PC、需要高质量渐变过渡的场景。 |
| **Floyd-Steinberg 误差扩散** | Error Diffusion | 将量化误差向右下邻域扩散，动态调整后续像素阈值。**特点**：灰度还原精度最高，但依赖像素间数据依赖，难以并行化；实时 Shader 中极少直接使用，多见于离线预处理或特定后处理节点。 | 离线图像量化、UI 复古风格特效；实时渲染中通常被 Bayer/Blue Noise 替代。 |

### 二、 按“时序处理机制”分类
抖动透明的视觉可接受度高度依赖抗锯齿与时序累积策略：

1.  **静态抖动 (Static Dither)**
    -   **原理**：每帧使用相同的噪声图案，不做任何时序混合。
    -   **表现**：近距离可见明显点阵/网格纹理，运动时产生闪烁与摩尔纹。
    -   **用途**：仅适用于固定视角、低分辨率复古风格，或作为调试基准。

2.  **时序抗锯齿协同抖动 (Temporal Dither + TAA/TSR)**
    -   **原理**：利用 TAA/TSR 的子像素抖动（Jitter）特性，使每帧的抖动图案在屏幕空间发生微小偏移；时序历史帧累积后，离散的点阵被融合为平滑的半透明渐变。
    -   **关键约束**：Dither 材质必须在 TAA Pass **之前**渲染并写入深度/速度缓冲，否则时序累积失效。UE5 文档明确指出 Dithered Opacity 的设计前提就是配合 TSR/TAA 使用。
    -   **表现**：宏观视角下达到以假乱真的半透明效果；关闭时序抗锯齿后退回粗糙点阵状态。

3.  **逐帧随机抖动 (Per-Frame Randomized Dither)**
    -   **原理**：每帧向噪声采样坐标注入时间变量，使图案完全随机化。
    -   **表现**：消除静态网格感，但引入高频闪烁噪声；需强时序滤波器才能收敛。
    -   **用途**：烟雾、火焰等本身具有混沌特性的粒子/体积效果。

### 三、 按“应用维度与功能”分类
依据作用对象与附加功能，抖动透明在实际项目中分为以下实现形态：

1.  **逐物体抖动透明 (Per-Object Dither Fade)**
    -   **实现**：在目标物体的 Fragment Shader 中集成 Dither + Clip 逻辑，通过 `_Dither` 参数控制透明度。
    -   **典型用例**：第三人称相机穿墙消隐（《碧蓝幻想 Relink》）、LOD 过渡淡入淡出、角色受击半透明反馈。
    -   **阴影注意事项**：检索材料确认，Shadow Caster Pass 中必须同步应用相同的 Dither Clip 逻辑，否则会出现“本体半透明但阴影仍完整投射”的视觉矛盾。Unity 中需在 ShadowCaster Pass 内手动添加 `clip(_Dither - threshold)` 代码。

2.  **全屏抖动后处理 (Full-Screen Dither Post-Process)**
    -   **实现**：作为后处理 Pass 对整屏画面应用抖动量化，不修改任何物体材质。
    -   **典型用例**：复古 CRT/GB 风格滤镜、特殊感知模式（如热成像/夜视仪）、全局色彩深度降级模拟。
    -   **特点**：统一视觉风格，但无法区分单个物体的透明度需求。

3.  **组合增强型抖动 (Enhanced Dither)**
    -   **Fresnel + Dither**：将菲涅尔边缘光输出乘以 Dither 阈值，实现“边缘先透明、中心后透明”的自然消隐，避免均匀点阵的生硬感。
    -   **Depth-Based Dither**：根据物体与相机的距离动态调整 Dither 强度，近处完全不透明、远处逐渐抖动消散，用于 LOD 无缝过渡。
    -   **Color-Matched Dither**：抖动丢弃的像素颜色参与周围像素的平均计算（需后处理配合），减少透明度变化时的亮度跳变。

### 四、 核心优势与局限（基于检索证据）
-   **优势确认**：完美支持延迟渲染光照/阴影、写入深度缓冲、无透明排序问题、兼容 MSAA、性能开销远低于 Alpha Blend。UE5 文档明确建议“任何半透明场景都应首先尝试 Dither Mask 替代”。
-   **局限确认**：无法实现精确的逐像素多层色彩叠加（仅有 0/1 遮罩）；未开启 TAA/TSR 时视觉质量显著下降；移动物体可能产生时序残影（Ghosting）；Shadow Caster 需额外处理以避免阴影不一致。

### 五、 尚未确认的部分
-   检索未找到针对“Dither Transparency”的统一行业标准分类术语体系，上述分类系依据 Unity/Unreal 官方文档、Shader Graph 源码及多篇技术博客的实现方式进行归纳。
-   关于 Floyd-Steinberg 误差扩散在现代实时 GPU 上的具体并行化实现方案及性能基准，检索材料未提供有效案例，仅确认其在实时渲染中被 Bayer/Blue Noise 取代为主流。如需该算法的实时应用细节，需进一步查阅计算着色器相关专项资料。
