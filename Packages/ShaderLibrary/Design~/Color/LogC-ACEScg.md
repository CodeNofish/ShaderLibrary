### 先分清一件事：这两个不是同一层级的东西

**LogC 是「摄影机原生对数编码曲线」（gamma 编码）**，必须搭配色域（AWG3 / AWG4）才构成完整色彩空间；**ACEScg 是「场景线性工作空间」**（AP1 原色 + 线性光），属于后期流程中的中间交换格式。前者负责把传感器数据尽量无损地装进文件，后者负责让合成、灯光、多来源素材在同一套物理正确的数学环境里运算。典型流程里它们是上下游关系，而不是二选一。

---

### 一、LogC（ARRI LOG Encoding）

#### 是什么
ARRI 为其 ALEV / ALEV III / ALEV 4 传感器设计的对数光电转换曲线，配套色域为 ARRI Wide Gamut（AWG3，Alexa Classic/Mini/LF 系列）与 AWG4（Alexa 35）。历经 LogC → LogC2 → LogC3 → LogC4 几代演进，其中 LogC4 配合 Alexa 35 可编码约 17 档动态范围，并采用了更宽的原色。

#### 优势
| 优势 | 说明 |
|---|---|
| **与传感器动态范围贴合** | 按档位分配码值，中灰以上大致每档占用等量码值，充分利用 10/12/16bit 的量化精度 |
| **高光滚降保留完整** | 不裁切、不压缩死白，高光过渡自然，给调色留出真正的“可拉回”余量 |
| **感知均匀** | 人眼对亮度变化敏感度近似对数，Log 编码在同等码率下视觉噪声分布更均匀 |
| **跨机型一致性** | 同代 LogC 在不同 ARRI 机型间匹配度高，一套 LUT 可复用，多机位调色省力 |
| **现场监看友好** | 挂载官方 LUT（Rec.709 / HDR）即可得到接近成片的监看画面，且 LUT 有 EI 版本可做曝光管理 |
| **归档价值高** | 作为“最接近原始传感器”的形态，是未来重制或改做 HDR 的理想母版素材 |

#### 使用场景
- **拍摄端与素材交付**：机内录制、DIT 转码、Daily 制作的标准起点。
- **现场监看**：加载对应机型与 EI 的官方 LUT，避免凭感觉判断曝光。
- **VFX 素材板（plate）**：为合成环节提供最大信息量，后续再通过 IDT 转换至 ACES。
- **HDR 母版与长期归档**：保留全部原始动态范围，应对未来格式迭代。
- **调色一级校正起点**：在 DaVinci 中使用 ARRI 官方 LUT 或色彩空间变换（CST）进入工作空间。

#### 常见坑
1. **把 LogC 当 Rec.709 看**——画面灰平属正常现象，切忌直接套用对比度或饱和度调整。
2. **LUT 版本错配**：LogC3 与 LogC4 互不通用；同一代 LUT 也有 EI 敏感型与通用型之分，用错会导致曝光偏移。
3. **误认为它是完整色彩空间**：LogC 仅代表曲线，必须明确搭配的是 AWG3 还是 AWG4。
4. **二次对数化**：若已进入 ACES 或 DWG 流程，切勿再叠加一层 Log 转换，否则会造成对比度异常。

### 二、ACEScg

#### 是什么
ACES（学院色彩编码系统）家族中的**场景参考线性工作空间**：采用 AP1 原色（R 0.713/0.293、G 0.165/0.830、B 0.128/0.045）、线性光（gamma 1.0）、无黑点与白点钳制，数值可远超 1.0 以承载真实光照强度。通常以 16bit half-float EXR 格式存储。需注意它与以下两个概念的区别：
- **ACES2065-1（AP0）**：更大色域的全浮点归档空间，主要用于母版存档而非日常运算。
- **ACEScct**：在 ACEScg 基础上增加类对数曲线，专为调色手感设计。

#### 优势
| 优势 | 说明 |
|---|---|
| **物理正确** | 线性光下，加法、乘法、缩放、模糊、景深、运动模糊等运算均符合真实光学规律，合成不易出现“塑料感” |
| **设备无关** | 脱离具体摄影机特性，不同品牌、不同年代素材可在同一空间内对齐 |
| **色域够大但不虚** | AP1 覆盖绝大多数实拍与 CG 可达颜色，同时避开不可实现的虚色，数值稳定性优于 AP0 |
| **无上限动态范围** | 光源、爆炸、镜头光晕等过曝内容能如实记录，不会被压死 |
| **标准化流程** | 具备官方 IDT（输入）、RRT/ODT（输出）与 LMT 规范，各软件、各厂商结果一致，减少沟通成本 |
| **面向未来** | 交付 Rec.709、P3、HDR10 或 Dolby Vision 时，只需更换 ODT，无需重做工程 |

#### 使用场景
- **CG 渲染输出**：Arnold、V-Ray、RenderMan 等渲染器的标准输出空间，发光材质与物理相机直接对应。
- **合成（Nuke 等）**：作为默认工作空间，merge、grade、glow、defocus 等节点在线性环境下行为正确。
- **多来源素材整合**：混合 ARRI、RED、Sony 及 CG 层时，先各自经 IDT 统一至 ACEScg 再行运算。
- **HDR 与影院交付**：作为通往 P3-D65、Rec.2100 HLG/PQ 的中转站。
- **长期资产归档**：结合 ACES2065-1 使用，确保十年后仍可无损重输出版本。

#### 不适合的场景
- **直接监看**：线性图像在普通监视器上会显得极暗且反差怪异，必须经过 ODT 转换。
- **剪辑与调色界面操作**：线性空间中调节 lift/gain 的手感极差，通常需转入 ACEScct 或 DaVinci Intermediate 后再调色。
- **低比特深度与强压缩环境**：half-float 是最低门槛，8bit 或 H.264 编码完全无法胜任。
- **轻量级快剪项目**：纯 Rec.709 或单条 LogC→709 流程效率更高，引入 ACES 反而增加负担。

### 三、两者怎么接在一起（典型管线）

```
拍摄：LogC4 + AWG4（机内 / ARRIRAW）
   ↓ IDT（ARRI 官方 Input Transform）
ACEScg（线性，用于 CG 渲染、Nuke 合成、光效运算）
   ↓ 可选：转到 ACEScct 或 DaVinci Wide Gamut-Intermediate
调色（一级 + 二级，手感友好）
   ↓ RRT/ODT 或自定义显示变换
Rec.709 / P3-D65 / Rec.2100 PQ-HDR 交付
```

**简化版（无大量 VFX 的项目）**：LogC → 调色空间（DWG 或 ACEScct）→ ODT → 交付。此时全程不必触碰 ACEScg。

---

### 四、一句话选型建议

- **手握 ARRI 摄影机**：拍摄阶段坚持使用 LogC（配合正确代际与 AWG），这是获取最大画质红利的关键。
- **涉及 CG、合成或多机型混拍**：尽早通过 IDT 转换至 ACEScg 进行运算，调色时再转入类对数空间。
- **纯纪录片、活动或短平快项目**：采用 LogC 配合监看 LUT 并直接在 Rec.709 下微调即可，无需强行套用 ACES。
- **无论选择哪种方案**：务必保证从拍摄到交付整条链路的色彩空间标注清晰一致，并在制作前使用测试卡验证 LUT 与变换配置，这比单纯纠结选用哪个空间更为重要。
